# Tech Note Writing

为 `notes/` vault 生成**问题驱动**的技术笔记。核心不是罗列知识点，而是复现"这套方案为什么必然长成这样"的推导链。

写作前先读 [REVIEW.md](REVIEW.md)（自检清单）和 [VAULT.md](VAULT.md)（vault 格式约定）。

## 核心理念：一条叙事链，三段式重复

每个组件/技术层都回答同一个三连问，读者读完任意一节都能说出"它站在哪、它不管什么"：

```
为什么必须存在（痛点）→ 接管到哪一层（边界）→ 剩下的是谁的活（甩锅）
```

这个三连问在正文里**至少重复三次**：引出主角时、引出它的上游/下游时、划能力边界时。它是防止笔记写成官方文档翻译的关键。

## 工作流程

```
写作进度：
- [ ] 1 定位：归属分区 + 相邻已有笔记
- [ ] 2 梳理叙事链，定详略
- [ ] 3 逐层引出（每层：解决什么 / 不管什么）
- [ ] 4 画完整数据流 + 逐段失败模式
- [ ] 5 划边界：自动获得 vs 必须配合改动
- [ ] 6 最小可运行实战
- [ ] 7 一句话总结 + 参考资料
- [ ] 8 过 REVIEW.md 自检
- [ ] 9 交付审阅 → 按反馈修订
- [ ] 10 落文件 + 登记 MOC
```

### 1. 定位（必须先做，决定重复与链接）

按 [VAULT.md](VAULT.md) 的分区映射确定归属目录。然后**通读该分区的 MOC 文件 + 相邻已有笔记**：

- 主题已有 ≥50% 覆盖 → 不新建，改为**扩写既有文件**，并在回复中说明"哪节是新增"
- 主题在别的笔记被引用过 → 新笔记要用 `[[wikilink]]` 接回去，而不是重讲一遍基础
- 版本、术语以既有笔记为准（避免同一组件两篇笔记互相矛盾）

### 2. 梳理叙事链

输出一句因果链，作为全文骨架的检验标准：

> 因为 A 问题，所以需要 B；B 只管 X，Y 仍缺，于是需要 C；C 与 B 的分工是 …；串起来得到 D 效果。

写不出这句 → 说明还没想清楚，不要开始动笔。同时定出各节详略：主线展开，旁支一句话带过并链接。

### 3–7. 正文 8 段骨架

见 [template.md](template.md)（可直接套用的填空骨架）。要点：

| 段 | 硬性要求 |
|---|---|
| 1 痛点 | 具体故障现象（延迟、失败模式、成本数字），禁止用"缺少统一方案"这类抽象定义开场 |
| 2 逐层引出 | 每层一对**「管什么 / 不管什么」**，"不管什么"用并列候选项点名（不是它该干的活、它不承担、不覆盖 X 场景） |
| 3 数据流 | Mermaid 图 + 逐段文字走查，标注每段的延迟/丢失/背压风险 |
| 4 能力边界 | 至少一张表：信号/能力 × 开箱可用 vs 需改动 × **具体改动点**。禁用"需要适当配置""做一些适配" |
| 5 场景与对比 | 什么时候不该用；对比同类工具 ≥3 个维度，且写"选 X 的代价"而不只写优点 |
| 6 最小实战 | 可跑通链路：容器/依赖 + 服务端 + 客户端；每条命令带预期输出；标注版本假设 |
| 7 一句话总结 | `它是〈类别〉，解决〈哪一段〉，不解决〈哪些〉；适合〈场景〉，不适合〈场景〉` |

### 8. 自检

逐条走 [REVIEW.md](REVIEW.md)。四组硬门槛：**知识点准确**、**边界表达不含糊**、**顺承无跳跃**、**符合 vault 格式**。**未过自检不得交付。**

### 9–10. 交付与登记

默认交付顺序：

1. 回复中给出**叙事链一句话 + 章节骨架 + 关键结论**，请用户确认方向
2. 方向确认后写全文（长笔记直接落文件；短笔记可在回复中展示供审阅）
3. 用户认可后按 VAULT.md 约定写入目标路径，并**登记 MOC**：更新所属分区的 `xx.md`（MOC）表格行 + `首页.md` 的板块进度
4. 更新 frontmatter 的 `updated`

## 输出格式约定（摘要）

详细见 [VAULT.md](VAULT.md)：

- frontmatter：`tags`（分类 + 组件名 + `教学`/`面试`/`实战`/`moc` 之一）、`created`、可选 `status: 已整理`
- 正文 `## 1. 标题` 数字章节；开篇 H1 + `>` 引述交代版本与整理依据
- 表格承载"边界 / 对比 / 字段 / 谁负责"；Mermaid 承载链路
- `[[wikilink]]` 指向**文件基名**（去 `.md`，保留空格与大小写）
- 文末 `## 参考资料` 列官方文档与版本
- 叙述中文，配置 key、字段名、命令行保持英文原样

## 常见跑偏

| 跑偏 | 纠正 |
|---|---|
| 开篇讲"XX 是什么" | 改成先讲没有它会遇到的具体故障 |
| 只写优点，说"推荐用于所有场景" | 补写选型的代价与失效场景 |
| 边界写成"基本都支持" | 改成表格逐项列 + 明确改动点 |
| 实战片段是伪代码 | 真实命令 + 预期输出 + 版本假设 |
| 章节间硬跳转（术语未定义就用） | 按叙事链排序，前向引用改为先定义 |
| 大段抄官方文档 | 用自己的话复述机制，官方内容放参考资料链接 |
| 与既有笔记重复 | 步骤 1 已发现重复 → 改为扩写或链接 |
