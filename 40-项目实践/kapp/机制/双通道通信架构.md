# 双通道通信架构

> 概念层见 [[长连接与通信]]；本篇是 kapp 系统的实例化：三链路、协议选型、channel 绑定。
> 参与方：[[apiserver]]、[[kapp-agent]]、[[pevent]]、[[kapp-web]]、Centrifugo（ops chart 部署）。

## 1. 三链路与连接形态矩阵

| 链路 | 协议 | 形态 | 谁发起 | 为什么 |
|---|---|---|---|---|
| apiserver → Centrifugo | gRPC | 短连接，每次 Dial+Close | apiserver | 偶发控制调用（Publish/PresenceStats），内网 :10000 无穿透问题 |
| Centrifugo → agent/前端 | **SSE**（uni_sse） | **长连接** | **客户端主动拨出** | 服务端需随时推送；客户侧无入站 |
| agent/pevent/前端 → apiserver | Connect | 短 POST | 客户端 | 请求-响应，一问一答 |
| agent ↔ pevent | 无直连 | K8s 对象协调 | agent 建 Job | 共享 kube-apiserver，见 [[组件部署流程]] |

判据：**谁需要"被对方随时找到"，谁才维持长连接**；长连接只留给下行推送段。
连接方向 ≠ 数据方向：SSE 由 agent 主动拨出，数据却由服务端推。

## 2. Centrifugo：协议转换枢纽

两张面孔：**进（服务端 API）gRPC，出（客户端连接）SSE**。

- 服务端 API 证据：`kapp/pkg/sse/grpclient.go` —— `grpc.DialContext` + `PerRPCCredentials`（metadata `authorization: apikey <key>`）+ `NewCentrifugoApiClient(conn).Publish`；每次调用建连、defer Close；双层错误（transport err + 响应内嵌 `centrifugo.Error`）。
- proto 来源：vendored `api/pb/third/centrifugo`（v5.3.1 api.proto）→ go-grpc 插件生成 `centrifugo_grpc.pb.go`，FullMethodName `/centrifugal.centrifugo.api.CentrifugoApi/Publish`。这是"第三方 proto 生成客户端桩"的活代码例子（对照 [[Proto契约与代码生成]] 中 agent 服务的死代码 _grpc）。
- 客户端连接：agent `pkg/sse/sub_new.go` POST `ConnectRequest{Token, Subs}` 到 `{SubServerURL}/connection/uni_sse` 后挂流；前端 `kapp-web/src/store/sse/SSEService.ts` 用 `EventSource` + `cf_connect` query 同款协议。
- 配置：`ops/charts/kapp/chart/templates/centrifugo.yaml` —— `CENTRIFUGO_TOKEN_HMAC_SECRET_KEY`（与签发 SubToken 同钥验签）、`API_KEY`/`GRPC_API_KEY`。

## 3. 协议选型：为什么不是 gRPC 到底

| 协议 | 本质 | 本系统位置 |
|---|---|---|
| RPC | 范式（像调本地函数一样调远程） | 总称 |
| gRPC | HTTP/2 + protobuf 帧 + trailer | 仅内网 apiserver↔Centrifugo |
| Connect | HTTP/1.1/2 + protobuf/JSON，兼容 gRPC/gRPC-Web | 所有跨边界上行 |
| SSE | 永不结束的 HTTP 响应（text/event-stream + JSON 帧），单向 | 所有下行推送 |

公网穿透：SSE/Connect 是普通 HTTP，任何七层 ingress/代理/防火墙都认识；gRPC 的 HTTP/2+trailer 易被中间设备破坏 → 只跑内网。上行要可 curl 调试 → Connect。下行单向且浏览器原生 → SSE。

## 4. channel 绑定与隔离（精确语义）

- **发起方是客户端**：agent 把 token 里的 channel 作为 `Subs` 主动上报；Centrifugo 不指派 channel。
- **值来自签发方**：安装时 apiserver `TokenGenerator(SSEServerKey)` 签 `{sub: clientName, subs: {clusterCode: {}}}`；agent `ParseTokenContext` 读出，不自选。
- **subs claim ≠ 权限白名单**：Centrifugo 官方语义是"连接时 server-side 自动订阅"；本部署未启用额外 channel 保护（无 $ 私有前缀/namespace/subscription token/subscribe proxy）。
- 隔离三层：① 连接 JWT 验签（同钥）；② channel 名（clusterCode）私密不可猜；③ 发布权（API key）垄断在服务端。
- 前端 channel 形态 `gpt:web-event#<userid>`（`#` user-limited 语义）。

## 5. 断线与心跳

- go-sse 自动重连；`disconnect` 事件 → agent `log.Fatalf` → K8s 重启兜底（fail-fast）。
- 空 `{}` 帧视为服务端心跳忽略；agent 业务心跳 = Connect `SetAgentStatus`（默认 60min ticker，5s 超时）。
- apiserver Publish 前 `PresenceStats` 在线检查，离线快速失败。
